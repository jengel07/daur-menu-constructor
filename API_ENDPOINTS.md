# Документация API проекта

В проекте API вызывается двумя способами: через централизованный клиент `src/api.ts` и напрямую через `axios` / `fetch` в некоторых компонентах. Ниже представлен полный список всех используемых эндпоинтов и за что они отвечают.

## Централизованный API (`src/api.ts`)

Этот файл содержит основные методы взаимодействия с бэкендом. Большинство эндпоинтов защищены и требуют наличия JWT токена (отправляется автоматически).

### 🔐 Авторизация (`authApi`)
* `POST /api/auth/register` — Регистрация нового ресторана/пользователя.
* `POST /api/auth/login` — Авторизация пользователя (возвращает токен и роль).
* `POST /api/auth/refresh` — Обновление JWT токена для продления сессии.

### 🍽 Меню (`menuApi`)
* `GET /api/menu?restaurantId={id}` — **Публичный** эндпоинт. Получение меню для клиентского телефона без авторизации.
* `GET /api/menu/{restaurantId}` — **Защищенный** эндпоинт (только для админа). Получение данных меню в конструкторе.
* `POST /api/menu/{restaurantId}` — Сохранение данных меню.
* `POST /api/parse-menu` — Парсинг загруженных файлов меню (например, Excel) и возвращение структурированных данных.

### 🛒 Заказы (`ordersApi`)
* `GET /api/orders` — Получение списка всех заказов для текущего ресторана.
* `POST /api/orders` — Создание нового заказа клиентом.
* `PATCH /api/orders/{id}/status` — Изменение статуса заказа (например, "в обработке", "готов", "отменен"). Также позволяет передать причину отмены.
* `DELETE /api/orders/{id}` — Удаление конкретного заказа.
* `DELETE /api/orders/all` — Очистка/удаление всех заказов.

### 👥 Персонал (`staffApi`)
* `GET /api/staff` — Получение списка сотрудников текущего ресторана.
* `POST /api/staff` — Добавление нового сотрудника и отправка ему email.
* `DELETE /api/staff/{id}` — Удаление сотрудника.

### 👑 Супер-администратор (`superAdminApi`)
*(Только для владельца всей платформы)*
* `GET /api/superadmin/stats` — Общая статистика платформы (кол-во ресторанов, заказов, сотрудников).
* `GET /api/superadmin/restaurants` — Список всех зарегистрированных ресторанов.
* `DELETE /api/superadmin/restaurants/{id}` — Полное удаление ресторана и его данных.
* `POST /api/superadmin/login-as` — Вход суперадмина под аккаунтом любого выбранного ресторана.
* `GET /api/superadmin/staff` — Список всех сотрудников всех ресторанов.
* `POST /api/superadmin/staff` — Создание сотрудника для любого ресторана.

## Внешние и прямые вызовы (без использования `src/api.ts`)

В некоторых компонентах запросы выполняются напрямую через `axios` или `fetch`. В будущем рекомендуется перенести их в `src/api.ts` для единообразия.

### Интеграции сторонних сервисов
* **Google Translate API** `GET https://translate.googleapis.com/translate_a/single...`
  * **Где используется**: `src/views/ClientView.vue`, `src/components/PhoneMockupContent.vue`.
  * **За что отвечает**: Динамический машинный перевод элементов меню на телефоне клиента (мокап и реальный интерфейс).

### Прямые вызовы API бэкенда
* `POST /api/staff/invite`
  * **Где используется**: `src/components/admin/InviteStaffModal.vue`
  * **За что отвечает**: Отправка приглашения сотруднику по email (использует жестко закодированный IP-адрес `http://192.168.31.240:3000`).
* `GET /api/menu/{restaurantId}` и `POST /api/menu/{restaurantId}`
  * **Где используется**: `src/Constructor.vue`, `src/components/MenuEditor.vue`.
  * **За что отвечает**: Получение и сохранение структуры меню. Дублирует логику из `menuApi`.
* `POST /api/orders`
  * **Где используется**: `src/components/CheckoutModal.vue`, `src/views/ClientView.vue`.
  * **За что отвечает**: Отправка заказа клиентом в базу ресторана. Дублирует `ordersApi.create`.
* `GET /api/menu`
  * **Где используется**: `src/components/admin/AdminDashboard.vue`
  * **За что отвечает**: Получение статистики и данных по меню для дашборда администратора.
